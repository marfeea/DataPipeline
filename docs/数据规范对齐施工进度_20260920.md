## 版本与使用

真实采集入口现在写入 `r2dreamer-aubo-ik-aligned-v4`。纯逻辑 `DatasetConfig()` 仍默认 v3，以保留旧调用方；显式构造 v4 writer：

```python
from DataPipe.config import ALIGNED_SCHEMA_VERSION, DatasetConfig
from DataPipe.hdf5_writer import HDF5TrajectoryWriter

writer = HDF5TrajectoryWriter(
    "new_output_directory",
    DatasetConfig(schema_version=ALIGNED_SCHEMA_VERSION),
)
```

v3/v4 不能混写。v4 reader 保留版本号；不允许把 v4 episode 静默降级写入 v3。回放从 manifest 读取版本；本轮历史兼容验证针对现有 8 维 v3，不声称支持更早的不同动作维数。

## 阶段 A：schema、写入与奖励边界

已实现：

- TCP pose、EE twist、抓取参考位姿、相对 EE 的完整抓取位姿、物体放置目标的 base/world 字段，观测均为 T+1。
- `transforms/T_w_b`：固定时保存一次，变化时按 T+1 保存。刚体变换、单位四元数、双坐标一致性均有校验。
- 位姿以及 v4 相机外参统一为 XYZW；相机标定可从 `obs/camera_calibration` 和兼容根路径读取，使用 hard link 避免复制。
- `action_commanded`、`action_applied`、IK 关节目标、实际发送关节目标、三类限幅标志，全部为 T。
- `tcp_displacement` 改由相邻实际观测计算，旧处理命令保留在 `diagnostics/processed_tcp_command`。
- v4 强制 `reward_status=not_defined`、`reward_valid=false`。保留原环境奖励和分量用于诊断。
- writer 在创建 partial 分片前拒绝缺失的 v4 状态和 applied action，不生成伪传感器值。

动作仍使用兼容 8 维容器：`[dx,dy,dz,0,0,0,tcp_angle,gripper]`；有效语义是 5 维。heading 是 base XOY 平面的绝对角目标，按 π 归一化，平移按 0.02 m 归一化。Flange-down 由控制器保持。旧阶段规划器输出但实际被控制器忽略的三维旋转增量，现在在提交前显式归零。

## 阶段 B：真实采集

已实现并经过 Isaac 运行验证：

- TCP 位姿来自实际 flange 状态及固定 TCP 偏置。
- 速度从 PhysX/Isaac 的刚体 COM 速度迁移到 TCP 原点，包含 `omega × (p_tcp - p_com)`，base/world 只改变表达轴；记录的是 TCP 的世界绝对速度在两套轴中的表达。
- 夹爪力来自 PhysX `get_dof_projected_joint_forces()`；运行时确认两夹爪是平移关节，单位 N。该量是沿关节运动轴的投影力，不是指尖接触力，也不是隐式 PD 执行器的估计值。
- 抓取位置来自任务配置，完整抓取姿态由 Flange-down heading 求解器生成；`grasp_pose_o` 相对任务配置的物体根坐标计算。
- 放置物体位姿来自 `TargetState.position_e/rotation_wxyz`。这些字段在配置中明确是物体根位姿，与 `grasp_tcp_position_e` 分开。
- applied action 根据最终发送关节目标的 FK 相对于 policy-start FK 计算，表示最后伺服子步目标，不代表实际达到的运动；诊断值不事后截断到 [-1,1]。
- 抓取/放置来源、对象标识、TCP 帧、动作尺度、容差、奖励及对象代理语义写入元数据。

`grasp_in_ee_pose_b/w` 的定义已写入字段属性：平移为 `p_grasp - p_ee`，旋转为 `R_grasp @ R_ee.T`，均在后缀指定的轴中表达。这相当于完整 EE 相对位姿经旋转换轴到以 EE 为原点的 base/world 平行坐标轴，不是只存位置差。
