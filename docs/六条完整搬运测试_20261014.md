# 六条完整搬运测试

目标：抽取抓取起点不是 state2（脚本索引 2）的六条 pick & place 路线，验证五个新的放置位置能否完成整段物理轨迹。固定抽样为 0→4、1→0、0→1、0→3、3→0、0→2，放置终点覆盖索引 0–4。抽样在执行前冻结，不根据结果挑选路线。

使用主采集入口 `collect_isaacsim.py`、`physical` 模式及 `--stable-placement`。历史轨迹仅提供抓取与运输的关节目标；放置使用本次真实抓取关系和五状态的新物体根位置。全部路线从初始场景开始，通过真实物理步执行，不初始化成已抓取，不使用逻辑携物，也不在初始化后写机器人/物体状态。

本轮 MVP 验收：

1. 六条不同的路线，所有抓取索引均不为 2，放置终点覆盖五个状态。
2. 每条从初始状态启动，保存真实关节/物体观测、执行动作、原生三相机图像和阶段信息。
3. 独立重算抓取、掉落、支撑和奖励时序，分别报告数据审计是否通过与任务是否成功。
4. 成功路线必须包含抓取、抬升、运输、下降、松爪、等待稳定、侧向退出和退出后观察；满足位姿与线/角速度门限，退出前等待末尾连续稳定不少于 0.25 s，退出后连续稳定不少于 0.5 s（沿用放置控制器的验收）。原任务奖励曾判成功但等待末尾重新不稳定时，不算完整稳定放置通过。
5. 失败路线保留原始记录并定位首个失败阶段；不得把 `passed`（数据审计通过）当作 `task_succeeded`。

固定参数：120 Hz 物理步、60 Hz 控制、接触速度求解迭代 4、自然场景、原夹爪力、抬升保持 0.35 s。放置使用配置中的速度、保持、渐进松爪、稳定等待及侧向退出参数。串行执行，避免同时运行多个 Isaac 实例争用 GPU。

批次工作区目录：`artifacts/pick_place_six_routes_20261014`。`manifest.json` 冻结路线、参考文件校验值、放置策略和执行源码；`status.json` 保存实际执行进度，每条路线保留独立采集目录、日志及审计报告。最终验收见批次的 `audit.json` 和 `RESULTS.md`。

实际验收结果：6 条均已获得有效物理记录并通过独立数据审计。原任务奖励判成功 5/6，完整动作阶段执行 5/6；沿用退出前后窗口末尾持续稳定验收时，通过 3/6（0→4、0→3、0→2）。

1→0 完成全部动作并最终放稳，但松爪等待末尾角速度 0.1934 rad/s 超过 π/18≈0.1745 rad/s 门限。3→0 完成全部动作并最终位姿/速度合格，但退出后规定观察窗口末尾连续稳定只有 0.317 s，不足 0.5 s。0→1 抓取曾验证，运输后相对 TCP 漂移 10.71 mm、旋转 12.50°，超过 5 mm / 5° 门限，因此未进入放置。原任务较早时刻判成功不替代后续窗口的稳定性检查。

0→3 首次原生相机启动失败，主入口以相同参数重试后获得有效记录；3→0 首次运行到退出观察时原生运行时崩溃，没有完整记录，保留后以相同参数重新运行，最终统计使用重测记录。六条抽样名单、执行源码、放置策略及原参考文件校验值均保持一致。未调整坐标、阈值或控制参数来让测试通过。

每条路线保存 `trajectory.npz`（实际关节轨迹）、`observations.npz`（实际物体/TCP/夹爪观测）、`trace.json`、三相机图片和独立复核报告。汇总表中的路线链接直达各自 NPZ；`trajectories.png` 展示六条实际物体/TCP 空间路径，PASS/FAIL 标注对应稳定复核。
