# 物理实验主流程接入与验收

日期：2026-10-13。用户要求查明后直接合并到主逻辑。

## 本轮交付与边界

主入口 `scripts/collect_isaacsim.py` 默认采用 physical 模式与 Isaac Sim 后端。
物理执行实现迁入 `scripts/pipelines/curobo_bootstrap/physical_execution.py`，原独立脚本作为兼容入口。
主入口负责路线参数、执行阶段、故障场景、数据输出、运行报告及自动物理审计。
执行器在子进程中运行，以隔离 Kit 的初始化和退出；主入口只在执行及审计都通过后返回成功。

两种输入方式：

- 新路线：复用现有 CuRobo/Legacy 参考产线，先在 evidence 中产生 `planning_reference`，随后重新初始化并物理执行参考关节目标。最终输出目录只保存物理数据。
- `--reference-run`：校验已有参考任务，直接进行物理采集，跳过规划。可省略状态索引；显式索引必须与参考一致。

本轮保留原参考生成逻辑，因此参考准备仍含混合执行和逻辑携物。最终物理采集阶段的状态写入禁令、动力学观测和实测结果独立验证，不把参考成功当作物理任务成功。
本轮未把参考生成改造成全程在线物理规划，也未接入 HDF5/RL 训练或改写奖励参数。

## 输出和结果语义

输出保留原 NPZ 字段集合；实际 q/dq、物体/TCP、两指接触与支撑观测、实际关节/夹爪目标及 T/T+1 奖励另行保存。
`object_attached` 全 false。终止后的尾随观测不进入有效训练转移。

`<output>_evidence/run_report.json` 的 `passed` 表示采集与独立审计通过。
`execution_passed`、`task_succeeded` 与 `outcome` 分别表示执行完成、任务成功和实际任务结局。
确认掉落或超时仍可得到通过数据审计的记录，进程返回 0；启动、执行、任务身份或审计错误返回 1。
失败/故障/未知结果保留原数据。所有 physical 记录的 `demonstration_eligible=false`，不自动进入旧成功归档。
即使物体证据完整，缺少逐帧非法碰撞和几何重叠证据时，完整奖励训练 `reward_valid=false`。

`--execution-mode hybrid` 保留旧流程、NPZ 成功契约和未显式选择 backend 时的 Isaac Lab 默认值。
旧图收集、state4 收集/复测、五状态 GUI 验收等调用已显式选择 hybrid。

## 验收标准

1. 主入口可用新路线或既有参考进入物理执行，并自动完成独立数据审计。
2. 初始化后机械臂和目标状态写入次数均为 0，不创建逻辑 attachment，控制帧来自真实物理步。
3. 自然、故障和未完成结果均保留；数据通过不等于任务成功。审计失败不能通过主流程。
4. 关节/夹爪实际命令与实测状态区分保存，观测和奖励按 T/T+1 对齐，奖励可独立重算。
5. hybrid 仍生成旧成功契约产物；physical 规划参考与最终实测产物分开，旧成功归档不误收新数据。
6. 物理参数正确下传，不符合参考身份或物理频率/保持窗口约束的请求在启动前拒绝。
