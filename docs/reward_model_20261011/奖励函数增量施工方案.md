## 2. 当前数据的证据边界

读取每条 `trajectory.npz`、`scene_snapshot.json`、`plan_report.json`，并按 plan 中的
`source_sha256.integrated_trace/integrated_report` 唯一匹配同次执行的 `trace.json/report.json`。
任务 ID/hash 必须一致；逐行关节 q/dq 与 NPZ 必须一致；时间步须为 1/60 s。
本轮 10 个输入文件计算前后 SHA256 相同，详情保存在每条 summary 的 `input_sha256`。

trace 含实测 TCP Base 位置、物体 World 位姿、关节速度与夹爪位置，足以计算几何候选项。
但其 free-space 段写入关节状态，转运物体使用逻辑 attachment，不能声称全程物理闭环抓持。
两份 report 的 physics contact headers/points 均为 0；原程序已注明缺失报告不证明无碰撞。
托盘几何诊断均 `hard_gate=false, passed=false`：0→2 有 22 帧、4→1 有 31 帧正分数。
这里仅称“几何重叠风险”，不把 CuRobo 分数解释为牛顿或实际穿透米数。

松爪阶段仅有 4 帧/3 帧，没有 ≥0.25 s 的松爪后稳定观测、承托证据和实测物体速度。
4→1 最后两指位置约 7.722/5.997 mm，也未达到候选开爪门槛（每指 ≥8.05 mm）。
故两条评分全部保留 `reward_valid=false`，确认成功奖金为 0；未知不等于证明失败。
既有 `passed=true` 是旧采集验收结果，本提案不会反向修改它。

## 3. 奖励定义

记 W 为物体、目标及 TCP 的统一 World 坐标系，四元数顺序 **wxyz**。Base TCP 用冻结
`T_WB` 转到 W；E 目标用 `T_WE` 转到 W。存在物体放置标定时优先使用
`placement_calibration.desired_object_pose_w`。姿态为完整 SO(3)，并非只比较 TCP heading。

每个 episode 新建一个 `PickPlaceReward`。`step(o[t+1])` 返回 transition
`o[t]→o[t+1]` 的 r[t]，初始观测不发 reward。原 NPZ 的 N 个轨迹样本并不自动等于
正式 HDF5 的 N 个动作；本轮明确是 **N 个观测、N−1 个 transition**，不伪造 o[N]。

候选函数：

\[
r_t=2\Delta A_t+2\Delta L_t+4\Delta P_t+2\Delta O_t
 +2I_{\mathrm{grasp,first}}+10I_{\mathrm{settled,first}}
 -0.1\Delta t-0.01\frac{\|\dot q_t\|^2+\|\dot q_{t+1}\|^2}{2}\Delta t
 -5I_{\mathrm{overlap,first}}-C_{\mathrm{failure}}.
\]

`Δ` 均为相邻观测间的特征差，长度 m、时间 s、角度 rad，关节速度 rad/s。
本轮报的是无折扣 `R=∑r_t`；不默认使用训练 γ=0.99，也不把它称为理论保证的 PBRS。

### 3.1 接近与竖直抬升

\[
A_t=\max_{k\le t,\,\mathrm{reach/close}}[1-d_{\mathrm{tcp,grasp},k}/d_{\mathrm{tcp,grasp},0}]_0^1,
\quad
L_t=\max_{k\le t,\,\mathrm{lift}}[(z_{o,k}-z_{o,0})/h_*]_0^1.
\]

没有对应阶段时保留已有 frontier；每项 episode 最多 +2，重复前后晃动不会再次发放。
lift 仅在两指绝对位置均 ≤5 mm 时计算。在线有效模式还必须有物理抓取确认。
离线无接触证据时，只允许“闭指且物体竖直上升”的代理测量，并保持 mask=false。
转运/放置项从 L 达到 0.5 后启用；该代理门槛不声称物理力闭合成功。

一般 pick 的 `h*=0.05 m` 是候选最小离台进度目标，并不是修改实际轨迹的 0.4 m 净空。
state4 使用现有预设局部低抬升 `h*=0.015 m`，配合原有水平退出/高位转运路线。
4→1 的水平退出 180 mm 不应当替代竖直抬升：lift frontier 只到约 0.764672，得 +1.529344。
本轮没有新增奖励驱动的路径规划；以后净空仍由现有路径与碰撞约束负责。

### 3.2 物体位置与姿态

\[
d_t=\|p_{o,t}-p_g\|_2,\quad d_0=\|p_{o,0}-p_g\|_2,
\quad \theta_t=2\arccos(|\hat q_{o,t}^{\mathsf T}\hat q_g|),
\]
\[
P_t=[1-d_t/d_0]_0^1,\qquad
O_t=[1-d_t/0.1]_0^1(1-\theta_t/\pi).
\]

启用前 P/O 初始化为 0；之后在 transport/place/release 段更新。位置与姿态都用有符号差分，
松爪后漂离目标会扣回信用；姿态奖励主要在距目标 100 mm 内生效，以免过早转向影响退出。
`q` 与 `−q` 等价，四元数先归一化，NaN/Inf、零四元数和不递增时间拒绝计算。

### 3.3 抓取、成功与失败事件

抓取奖金 +2：物理抓取证据确认后只发一次。不能由 CLOSE/PICK 指令、逻辑 attachment 或
旧 `passed` 直接置真；两条历史轨迹的抓取奖金均未发放。

成功奖金 +10：必须有已确认抓取，并在 release 阶段同时满足以下条件，**连续保持 0.25 s**：

- 物体位置误差 ≤20 mm，完整姿态误差 ≤10°；
- 两指绝对位置均 ≥8.05 mm（现有全开 11.5 mm 的 70%）；
- 物体线速度 ≤0.03 m/s，角速度 ≤10°/s；
- 已确认由目标承托、真实物理演化且证据完整；目标处支持接触允许，非法机器人环境接触不允许。

第一帧符合条件仅开始计时，不能把 release 前闭指时间算进 dwell。
在 60 Hz 下至少需要两端点覆盖 15 个稳定时间间隔；成功后禁止再次发奖。

失败互斥优先级：非法物理接触 −25 > 关节限位 −10 > 掉落 −10 > 稳定成功 +10 > 超时 −15。
安全失败当步同时取消所有正奖励，并标记终局。timeout 是截断，接入时不可误作吸收终态。
本轮没有足够证据判断非法物理接触/掉落/限位/超时，因此这些事件项暂为 0，mask=false。

几何重叠风险 −5 每回合一次，不改变 collector 的硬门禁或终止；两个 report 只有分段汇总，
无法定位首个重叠帧，离线评审将费用放在首个受影响段的**末帧**，CSV 会明确该段。
这一回溯归因不可复制为在线时序。在线若接入，必须逐步查询已排除合法接触的几何信号，
实际非法接触则走 −25 终止路径，避免把“只罚一次风险”理解为后续可以持续碰撞。

关节平方速度是运动强度代理，不是电能或扭矩成本；本版本也未引入 jerk、抓力优化等奖励。
0.1/s 时间代价鼓励完成后结束，减少只靠接近/闭爪等待刷分的动机。

## 4. 期望行为及可验证表现

| 候选机制 | 期望行为（设计推断） | 本轮可核查表现 |
|---|---|---|
| 接近 frontier | 朝实测抓点推进，避免反复离开又回到同一点刷分 | oscillation 测试再次靠近不给新信用 |
| 物理抓取奖金/竖直 lift | 真实闭指夹持后离开支撑；state4 先局部低抬再按旧路线退出 | 水平位移测试 lift=0；有效模式未确认抓取不给 lift |
| P/O 有符号差分 | 把物体运到目标并对齐瓶姿态，松爪后维持原位 | 4→1 release 段净 −0.370875；远离目标测试扣回信用 |
| 一次 +10 和稳定 dwell | 完成承托与松爪后静置，不能夹着瓶子在目标处冒充放置 | 缺承托/速度/完整开爪、姿态错误均不给 +10 |
| 时间/速度代价 | 及时完成、减少无用等待与运动强度 | 相同一秒等待在 4/60 Hz 都累计 −0.1 |
| 几何风险和安全终止 | 减少托盘擦碰、遇实际非法接触不靠成功奖覆盖 | 两路均扣风险 −5；安全失败覆盖同步成功和超时 |

这些是奖励意图及单元/离线证据，不是已训练策略的行为保证。学习效果须另做训练和真实物理
回放验证；state4 的低抬升和路线差异说明奖励必须按任务条件归一化，不能单纯鼓励更高抬升。

## 5. 增量实施与待批复接入

### MVP-A：本轮离线提案（已完成）

1. 纯 NumPy 模型 `scripts/pick_place_reward_candidate.py`，与 Isaac/CuRobo/正式环境解耦。
2. CLI `scripts/evaluate_pick_place_rewards.py`，按源哈希取证、只写独立 sidecar。
3. 18 个行为测试；全仓库 148 项回归通过；新增源码 Ruff 通过。
4. 两条轨迹输出 JSON/CSV、文献卡片和完整数值；原始输入哈希保持。

验收标准：T=N−1、terms 逐行求和等于 reward、累计求和等于 summary、全部值有限；
两路值与上表误差 ≤1e−9；训练 mask 全 false；源 trace/report 哈希匹配并保持不变；
采集入口不导入新 reward 模块；成功等待、错误姿态、水平假抬升、重复刷奖和安全覆盖测试通过。

首次运行全回归时，33 个既有临时目录 fixture 被系统 Temp 权限阻挡。将 pytest basetemp
显式放在工作区新目录后，148 项全部通过，没有改动既有测试或采集代码来绕过检查。

### MVP-B：用户批复后的 shadow 标注接入（本轮未实施）

接入位置应在每步动作推进、reset 前终局观测捕获后，只读取现有状态与新增只读证据。
为未来真实采集准备独立 `RewardObservation` adapter：补物体实测位姿/速度、左右指有效接触、
目标承托、drop/limit/illegal-contact 和逐步几何信号，转换 quat **xyzw→wxyz** 必须显式。
现有 v4 `aligned_snapshot` 有配置构造的源物体 pose，不能拿它替代物体实际反馈。

新 adapter 接到 `PickPlaceReward(task,o0)`，每次 `step(o[t+1])` 形成 r[t]；
默认配置 `reward_mode=legacy`，只有批复的新模式 `pick_place_candidate_v1` 明确开启时运行。
单回合必须连续维护 frontier、抓取已发奖标志、P/O、稳定计时和风险标志；训练侧若要求完整
Markov 状态，应将这些记忆作为独立 reward-state 元数据/观测，不能在切片窗口随意重置。

shadow 阶段先写独立 `reward_sidecar`，并只读观察正式采集 outcome，不用候选终止驱动状态机。
旧 `reward`、`reward_valid`、`done` 不被替换；观测证据完整的标签才可在新数据副本中置 valid。
真实接触传感器可用性及逐步几何执行成本仍待实测；不能承诺历史 run003 数据仅回填就能全部有效。
shadow 不额外推进物理，也不延长现有 release；因而当前短 release 的最终成功仍会是未知。
不可声称只增加 logger 就能补出 0.25 s 的真实观测。

验收标准：关闭新模式时同 seed 的命令、物理推进次数、原字段与旧成功判据一致；
启用时动作序列和采集结果相同，仅多出 sidecar；纯物理成功、错误放置、抓取失败、掉落与
超时各有一条新证据；逐步奖在 `[T]`、mask 为 bool、观测 `[T+1]`；无未来信息用于在线奖励。
证据缺项必须保留 mask=false 并注明原因。历史重叠回溯标注不得进入在线 adapter。

### MVP-C：批复并通过 shadow 验收后正式数据标注（后续）

现有记录类是 `scripts.records.StepRecord`，有 `reward/reward_components/reward_valid` 字段；
但 **v4 不是已经支持有效奖励的数据版本**：`scripts.aligned_schema.write_alignment` 强制写
全 false 的 mask，`FILE_METADATA.reward_status=not_defined`；`validate_reward_mask` 和
validator 拒绝任何 true。因此不能仅给 StepRecord 赋值就声称完成主数据接入。

后续应新增显式的 reward-aware schema/data family（版本名需接入时冻结），保留原 v4
读写分支与全 false 规则。新增模式为 StepRecord 写计算值/分量/逐步 mask，经新 writer
分支落盘；reader、validator、batch adapter 同时按版本区分 `not_defined` 与候选/有效标注。
不能直接放宽全部 v4 文件的 mask 校验。metadata 至少保存 model version、配置 SHA256、frame/quat、
source/destination、evidence mode、原始输入摘要与候选 outcome；不能混入旧 dataset manifest。
训练用新 reward 配置须重新检查 `RewardLossConfig` 中连续目标范围与 >0.5 正例权重，
本 reward 有负值与 >1 事件值，不能默认为概率标签。

候选 `terminated`/timeout 先只作为 reward outcome 元数据。若要同时改变 collector 或
CurriculumRL 正式 RL 终止与奖励，另行按项目边界从外部公共接口发布，再审查终局时序。
旧数据不原地回填、不覆盖；开关关闭即可继续旧采集路径。
若原 collector 没有足够的 release 后窗口，完整成功标签须在单独批复的新模式里增加物理
settle 验证段，或运行独立验证回放；验证段的 observation/time/action 另立契约，不能冒充旧
轨迹同一末帧已经发生的结果。独立回放只能提供独立验证结果，不能把回放 outcome 无标记地
回填为原采集的真实终止。该扩展不是本轮 shadow logger 的隐含行为。

验收标准：validator、reader、reward loss mask 与回放测试通过；成功、安全失败写 terminal，
timeout 只作截断；新 manifest/version/config hash 可追溯；旧采集输出和原数据摘要不变。
旧 v4 的非法 true-mask 仍必须被拒绝；新数据版本的合法逐步 true/false mask 可以正确读回。
接入提交仅包含本增量，不能带入当前工作树已有迁移/恢复改动。
