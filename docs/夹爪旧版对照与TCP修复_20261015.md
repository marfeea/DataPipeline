# 夹爪旧版对照与 TCP 修复（2026-10-15）

对照基准是工作区 `artifacts/0_to_4_gui_retest_20261014_keyframes/0_to_4`
中 `task_succeeded=true` 的物理执行记录，以及它引用的
`DataPipe/data/five_state_bidirectional_gui_20261009/0_to_1` 规划记录。
前者证明 0→4 实际抓放成功，不能据此宣称旧版 0→1 物理执行成功。

| 项目 | 旧版处理 | 当前处理 |
| --- | --- | --- |
| 夹爪控制 | 两个移动关节的位置目标，物理驱动与接触产生夹持 | 保持相同的 DatasetGripperController |
| 张开位置 | UpperFinger=0.0115 m，DownFinger=-0.0115 m | 相同 |

| 新增渐闭 | 无 | 诊断中试过的 0.5 s 渐闭及额外停留已从正式流程撤回 |
| 夹爪球模型 | fixed_open_components，144 个夹爪球 | 球坐标、半径与旧版逐项相同 |
| 全机器人球数 | 391 | 391 |
| 托盘接触策略 | 已保存旧轨迹为 run003，分数仅诊断 | 新生成命令默认 strict；复现旧策略须显式 --contact-policy run003 |

旧版 0→1 规划报告本身也记录 `support_tray_11` 正分数，例如进近段最大
0.0098492419。因此不能把旧版“成功生成轨迹”解释成“严格托盘碰撞门禁为零”。
`run003` 不绕过任务成功、真实夹持或放置稳定性的物理验收，但它也不提供严格无碰撞保证。
默认 `strict` 没有被静默更改。

## TCP 与坐标

五组 `pre_grasp_tcp_position_e`、`pre_place_tcp_position_e` 保持用户指定值，
分别作为闭爪前、松爪前的直接 TCP 目标。物体根位置仍用于初始化和成功判定。

原项目 TCP 与夹持中心在工具坐标中相差 (-0.045, 0, -0.017) m。
当前显式标定为 `grasp_center_tcp/1`，法兰到 TCP 平移为
(-0.18786, 0, 0.15805) m，控制 FK、IK 与新的规划 URDF 同步。
旧 URDF、旧碰撞模型和旧轨迹均保留；历史轨迹不能冒充新标定轨迹直接复用。

独立桌面 GUI 抓取探针 `gui_probe_02` 实测垂直抬升 0.439283 m，
最终夹持证据通过，保存 348 张原生图片。这个探针使用渐闭，
只能证明显式 TCP 标定和物理夹持可行，不能作为恢复旧版直接闭爪后的验收。

本轮结果：恢复旧版闭爪后的正式 GUI 尝试在相机初始化阶段失败，记录帧数为 0。
